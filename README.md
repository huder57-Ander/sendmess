# ms-wazzup-notify

Уведомление клиента в MAX (с фолбэком в Telegram через Wazzup24) при смене
статуса заказа покупателя в МоёмСкладе на «Доставляется».

## Файлы

- `ms_wazzup_notify.py` — сам сервис.
- `requirements.txt` — зависимости.
- `amvera.yml` — конфиг для Amvera (аналогично проекту с мостом T2).
- `.env.example` — какие переменные окружения нужны, с комментариями.

## Порядок разворачивания

1. **Новый репозиторий / проект**, отдельный от моста T2 (см. предыдущее
   сообщение почему).
2. В МоёмСкладе, если ещё нет — создать доступ к общему JSON API (логин/пароль
   пользователя с правами на заказы покупателей и вебхуки). Это НЕ ключ
   Phone API, который уже используется в мосте T2.
3. В Wazzup24 — подключить каналы MAX и Telegram, скопировать их `channelId`
   (Настройки → Каналы), и API-токен (Настройки → API).
4. Найти в карточке заказа покупателя реальные названия доп. полей трек-номера
   и ссылки отслеживания, заменить `MS_TREK_ATTR`/`MS_LINK_ATTR` в конфиге
   (пока там заглушки `Number_DL`/`Link_DL`).
5. Задеплоить на Amvera (`amvera.yml` уже в комплекте), задать переменные
   окружения по образцу `.env.example` — включая `PUBLIC_URL`, который Amvera
   выдаст после первого деплоя (сначала можно задеплоить с примерным
   значением, потом поправить на реальный домен и передеплоить).
6. При старте сервис сам зарегистрирует оба вебхука (в МоёмСкладе и в
   Wazzup24) — руками в кабинетах ничего кликать не нужно, кроме шага 3.
7. Проверить `GET /health` — должен ответить `{"ok": true, "pending": 0}`.
8. Провести тестовый заказ: перевести в статус «Доставляется», проверить
   логи — должны появиться строки об отправке в Wazzup.

## На что обратить внимание после первого теста

- Если статус клиента (`state.name`) в МоёмСкладе называется не точно
  «Доставляется» — поправить `MS_TARGET_STATE`.
- Логика подтверждения доставки в MAX сейчас консервативная (см. комментарий
  в начале `ms_wazzup_notify.py`): любой вебхук от Wazzup без ошибки
  считается успехом, явная ошибка или отсутствие вебхука за 15 минут —
  дублирование в Telegram. Когда увидишь реальные вебхуки о статусах —
  пришли пример, ужесточим проверку под точное значение `status`.
- `STATE_FILE`/`PENDING_FILE` обязательно должны быть на постоянном диске
  (`/data/...`), иначе после рестарта контейнера возможны повторные
  уведомления по заказам, которые уже были обработаны.
